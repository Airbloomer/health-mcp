# P1 current spec

This file is the current P1 spec. It replaces the issue body where that body still shows superseded text (`evidence_sha256`, observability enabled, a single deploy token).

The pilot keeps the registry on the one Airbloomer Cloudflare account. A separate registry account is mandatory before a third tenant, and Security re-reviews before tenant 3 is provisioned, or by 2027-01-31, whichever comes first.

P1 does not deploy. Nothing here runs `wrangler deploy` or writes to Cloudflare.

## Registry

D1 name `hmcp-pilot-registry`. Resource names use the `hmcp-pilot-` prefix (`BILLING_TAG` plus a hyphen) and Workers set `BILLING_TAG = "hmcp-pilot"`.

The registry Worker binds only that database, has no routes, and is the only Worker that holds `CONSENT_EVIDENCE_HMAC_KEY_<version>`. The current version is the non-secret var `CONSENT_EVIDENCE_KEY_VERSION`. Dev, CI-test, and pilot use distinct namespaces (`dev-1`, `ci-test-1`, `pilot-1`). The CI-test version is never a pilot key id. Old versions stay until every row is re-hashed. The re-hash steps are in `pilot/docs/hmac-rehash.md`.

Schema: `pilot/registry/migrations/0001_registry.sql`.

- `evidence_hmac` and `evidence_key_version` on each consent. There is no `evidence_sha256` column and no plain SHA-256 of evidence.
- HMAC-SHA256 over the stored evidence bytes. Tests use a synthetic key only.
- The SMS copy lives in `consent_evidence` as age ciphertext. The owner role is the only reader. Retention is the life of the account plus 3 years.
- No health data, phone numbers, plaintext tokens, or full token hashes. `token_meta` stores an 8-hex prefix. Tokens are CSPRNG, at least 32 bytes, URL-safe, and never user-chosen.
- `deleted_at` requires `deletion_requested_at`. Activation at `approved` or later requires a consent that has not been withdrawn.
- Events are metadata only. Export actions are `export_requested`, `export_delivered`, and `export_operator_copy_deleted`.

## Tenant config

`pilot/templates/wrangler.tenant.toml.tmpl`

- One D1 binding, named `hmcp-pilot-<tenant id>`, which matches the Worker name.
- `TENANT_ID` matches the name, the D1 name, and `<id>.health.airbloomer.com`.
- `workers_dev = false`, `HEALTH_STORE_RAW = "false"`.
- `HEALTH_METRIC_ALLOWLIST` is the summary set only. The pilot opts into no sensitive types.
- No URL token. Observability is off, `invocation_logs` is false, and there is no Logpush or Tail consumer.
- Rendered files are gitignored. CI masks the account id and the D1 id and does not print the rendered file.
- A rendered tenant config must not name `hmcp-pilot-registry` or a distinct registry account id.

Bearer auth only. `HEALTH_INGEST_URL_TOKEN` stays unset.

## Tokens and CI split

Cloudflare has no GitHub OIDC for API tokens, and a token cannot be limited to one Worker or one D1. Compensations, recorded in `docs/cf-access.md`:

- TTL 90 days and a client IP filter.
- GitHub environment secrets with a required reviewer. Never a repo or org secret.
- Rotate every 90 days and immediately on any personnel or access change. Rotation dates are `not issued` until a token exists.

`registry-admin` holds `REGISTRY_ADMIN_TOKEN`. A required reviewer must approve each run, and that reviewer cannot be the person who triggered it.

`pilot-tenant-deploy` holds `PILOT_TENANT_DEPLOY_TOKEN`. Tenant workflows must not reference `registry-admin` or its secret, and they must not deploy a script named `hmcp-pilot-registry`. The registry workflow must not reference `pilot-tenant-deploy`.

## Audit alerts

`pilot/src/audit.mjs` notifies the owner on every Worker deploy and every secret change (create, update, or delete) on the account. Tenant and registry workflows call that hook. The alert does not copy secret values.

## Access

`docs/cf-access.md` uses role labels only. It states that 2FA is required for every member, that no Global API Key exists or is in use, the time-box above, and this residual-risk line:

An account-scoped tenant deploy token can technically reach the registry Worker/D1; mitigated by CI separation, environment reviewers and audit alerts.

The owner acknowledges that line by signing off on the pull request.

## Plan

The pilot stays on the Cloudflare free tier. The recorded plan is: free tier; upgrade when a real limit is hit.

Tenant workers stay within 10 ms of CPU per invocation and 100,000 D1 rows written per UTC day. At 80 percent `src/core/free-tier.js` logs one JSON line (`limit_approaching` or `limit_reached`) for `worker_cpu_ms` or `d1_rows_written`, with `used`, `cap`, and that plan string. A write that would pass the daily D1 cap is not issued. CPU is sampled only when the runtime user agent is `Cloudflare-Workers`.

## Usage

D1 metrics are kept 31 days. Two UTC crons, `30 0 16 * *` and `30 0 1 * *`, pull the month. Days 1-15 come from the day-16 pull. Days 16 through the end of the month come from the day-1 run. Merge keeps a day only from the pull that owns it, so the result does not depend on where the 31-day retention boundary falls.

The query uses lowercase `string` scalars and `sum { cpuTimeUs }`. It does not hardcode `databaseId_in` or a storage `max` block; both are TODOs until authenticated introspection. CSV columns are `month, resource, requests, cpu, d1_rows_read, d1_rows_written, storage_bytes`.

## CODEOWNERS

`.github/CODEOWNERS` is required before P3. It covers `/pilot/HEALTH_MCP_REF`, `/.github/workflows/`, `/pilot/templates/`, and `/pilot/registry/migrations/`. The reviewer and security-reviewer role teams must be required reviewers before P3. The ancestor check does not stop a self-merged pin bump.

## CI

- `HEALTH_MCP_REF` is a 40-hex commit and an ancestor of `origin/main` (`git merge-base --is-ancestor`).
- Actions are pinned to a full SHA with a version comment.
- Top-level `permissions: contents: read`.
- No `pull_request_target`. Pull-request workflows have no secrets.
- Wrangler is pinned in `pilot/package-lock.json`. Dependabot covers npm and GitHub Actions.
- Gitleaks runs in CI. Gitignore covers `tenants/*.rendered.toml`, `*.secret`, `.dev.vars`, and `.wrangler/`.
